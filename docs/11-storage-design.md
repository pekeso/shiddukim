# Storage Design

## Provider

Cloudflare R2 is used for object storage.

## Stored Files

The platform stores:
- member profile photos
- generated member cards
- marriage request PDFs
- medical referral PDFs
- uploaded supporting documents
- future medical exam results

## Bucket Strategy

MVP can use one private bucket:

church-platform

Inside the bucket, organize objects by domain:

- members/photos/
- members/cards/
- marriage/requests/
- marriage/referrals/
- documents/uploads/
- future/medical-results/

## Object Key Rule

Never use personal data in object keys.

Bad:
members/photos/Jean-Mwamba-0812345678.jpg

Good:
members/photos/2026/05/uuid-random.jpg

## Access Model

Frontend never accesses R2 directly using permanent URLs.

Access flow:
1. User requests document through backend API.
2. Backend checks authentication.
3. Backend checks RBAC permission.
4. Backend checks ownership or assignment.
5. Backend creates short-lived signed URL.
6. Backend logs access event.
7. Frontend uses signed URL.

## Signed URL Expiration

Default expiration:
- 5 minutes for view/download
- shorter for highly sensitive files if needed

## Document Metadata

Store metadata in PostgreSQL:
- document code
- owner type
- owner ID
- R2 object key
- MIME type
- file size
- checksum
- document type
- created by
- generated by
- status

## Deletion Policy

Use soft delete in the database.

For MVP:
- do not physically delete R2 objects immediately
- mark documents as deleted
- prevent future access
- physical deletion can be handled by retention policies later
